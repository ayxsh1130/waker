# Troubleshooting

## Docker or port errors

Start Docker Desktop's Linux engine. Run `docker info`, then `docker compose config --quiet`. Ports 5173, 8000, 3000, 9090, 16686, and 8025 must be available. Stop conflicting local development processes or update both the relevant Compose port and matching frontend/CORS settings deliberately.

If memory is limited, start with `scripts/start.ps1 -CoreOnly`. The full model and monitoring stack uses more RAM and disk than the API/worker core. Image pulls and model downloads require network access; once cached, local workload execution does not require a hosted LLM.

## Database credentials

`POSTGRES_PASSWORD` configures the container's initial database password. `DATABASE_URL` must use the same password. Update both when changing them. URL-encode special characters in a connection URL or use a long generated alphanumeric password.

Changing `.env` does not change a password inside an existing PostgreSQL data volume. Change the database password explicitly or use the destructive development reset only when you are prepared to lose the data. Do not delete results merely to fix a configuration mismatch.

Migrations run through the one-shot `migrate` service before application processes start. Inspect `docker compose logs migrate` if startup waits there.

## All tasks fail with profile authorization errors

The internal control token is generated by `init-secrets` into a shared volume. Check that it completed successfully and each internal service mounts the same `control-secrets` volume. The token must never be copied into the frontend or a screenshot.

If that volume was removed independently while services remained alive, recreate the stack so all services observe the regenerated file. The backend and workers read the token from the mounted file when making requests.

## Worker is offline or queue is stuck

Inspect `docker compose logs --tail=100 control worker worker-control broker-proxy`. A worker-crash fault intentionally leaves the supervised child down until cleanup or an approved restart. A broker fault intentionally closes only the experimental worker's proxy path.

The controller marks an interrupted idempotent task LOST after heartbeat loss; Redis visibility/redelivery may take longer. Do not relabel it SUCCEEDED. The experiment runner waits for outstanding tasks and can block after three minutes instead of contaminating another trial. Resolve the worker/broker state, then create a new experiment for a clean protocol.

The controller holds a singleton PostgreSQL lock. Running a second controller is rejected. Restarting the controller marks interrupted investigations/trials explicitly and schedules active fault cleanup. An action interrupted in EXECUTING becomes UNCERTAIN and is not replayed.

## Model or retrieval is unavailable

Check `.env` and recreate backend/control after changing it. Groq/compatible errors and rate limits appear as blocked investigations. A model name existing in an example does not guarantee continued provider availability or tool support. Select a supported model in your provider account.

Retrieval loads a local CPU model on first startup. Check `docker compose logs retrieval` for download or dependency errors. Its health endpoint remains unavailable while loading. Core task execution does not wait for embeddings.

Changing the embedding model is an index migration. The service refuses to silently mix a new model into the old collection. Preserve exports and use a separate/new Chroma volume plus an explicit reindex procedure; do not mix vector dimensions or pretend distances remain comparable.

An empty history is expected until a verified, executed recovery has occurred. Dry-run proposals and quarantine outcomes do not enter recovered history.

## Diagnosis is unverified or retry is denied

Read the verification record's missing evidence and contradictions. Source types, collected evidence IDs, and component consistency are checked separately from model confidence. A high confidence number cannot override missing evidence.

Retry requires a FAILED idempotent task with no quarantine. An already succeeded, active, non-idempotent, or quarantined task is ineligible. A prior failed action or active cooldown can also deny it. Review the policy reason rather than repeatedly submitting the same request.

An existing dry-run proposal does not change into an execute action when `.env` changes. Create a fresh investigation/diagnosis so the new policy decision has an explicit audited mode.

## Charts have blanks

Blank values mean no valid measurement. A healthy control has no diagnosis accuracy value. A dry run has no MTTR. A provider that does not report tokens has unknown token usage. A missing cost configuration has unknown estimated cost. None of these should be converted into zero merely to make the chart look populated.

## Application sign-in

If `APP_AUTH_ENABLED=true`, use the application ADMIN_TOKEN in the sign-in form. It must be at least 32 characters. It is not your Groq/OpenAI-compatible key. The form sends it directly to the backend, which returns an HttpOnly session cookie.

Use the exact configured frontend origin. Switching between `localhost` and `127.0.0.1` changes the origin. Production mode requires a deliberate HTTPS deployment and secure cookies; the default Compose quickstart is for local development only.
